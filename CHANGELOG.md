- Added the pure `ExecutableLaneSelection` 1.0 selector (`agent-os-executable-lane-selection`, AOS-QUEUE2, #864, approved in #855): `scripts/agent_os_candidate_packet/executable_lane_selection.py` classifies every supplied issue -- given its canonical `IssueOperationalState` (#862) and `AgentOperatingModeDecision` (#863) -- into exactly one of `ready-for-implementation`, `ready-for-review`, `waiting-for-authorization`, `waiting-for-dependency`, `merged-needs-closure`, `needs-reconciliation`, `planning-only`, `terminal`, `invalid`, then selects up to `requested_lane_count` (1-3) productive lanes. Precedence: explicitly requested executable issues in caller-supplied order, then other independently executable issues, then permitted `ready-for-review` issues, then reconciliation work, then planning-only; waiting and terminal issues stay visible but never consume a lane. Ties break on explicit request position, then ascending dependency depth, then ascending issue number -- no timestamp, popularity, model score, or live GitHub state is consulted. Lane replacement only substitutes for an explicitly requested issue that lands in a blocked queue, only when both `substitution_allowed=True` and the candidate's own `substitutable=True`; the substitute is the next eligible independent (`ready-for-implementation`) issue, recorded as a `ReplacementRecord` with a finite reason code, and an exact-required (`substitutable=False`) blocked issue is never silently replaced. Multiple active primary claims classify `needs-reconciliation`, are recorded as a `DuplicateClaimFinding`, and are always excluded from lane selection regardless of lane count or substitution policy; exactly one active primary claim is excluded from new implementation and reaches `ready-for-review` only when the supplied mode evidence permits review. The immutable result carries schema name/version, campaign ID, requested lane count, substitution policy, sorted supplied issue numbers, sorted-unique source `state_id`/`decision_id` identities (never the nested upstream records), every issue's `QueueClassification`, `selected_lanes`, `deferred_candidates`, `replacement_records`, per-issue `RankEvidence` (rank, tier, explicit-request position, dependency depth), `duplicate_claim_findings`, finite `reason_codes`, and fixed `execution_authorized=False` / `side_effects_performed=False`, with deterministic canonical JSON, a domain-separated SHA-256 `selection_id`, strict schema/version/unknown-field rejection, and a byte-stable round trip. Performs no GitHub, network, filesystem, subprocess, Scheduler, provider, credential, production, or external-system call, and no issue/label/branch/commit/PR/comment/merge/closure/repository mutation; queue placement never widens, infers, or collapses an authority field the supplied inputs already carry. - Added the pure `AgentOperatingModeDecision` 1.0 evaluator (`agent-os-operating-mode-decision`, #863, approved in #859): `scripts/agent_os_issue_acceptance/operating_mode.py` intersects a requested mode's capability ceiling (`planning`, `build`, `draft-pr`, `review`, `release`) with the canonical `IssueOperationalState` from `issue_operational_state.py` (#862) and caller-supplied `EnvironmentCapabilityEvidence` (local-execution and push capability), consuming the state's six existing authority projections directly rather than re-deriving or duplicating a second authorization framework.
