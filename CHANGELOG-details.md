# Changelog — Historical Details

Older `0.1.1-draft` entries moved from `CHANGELOG.md` to keep the canonical changelog under the repository Markdown line limit. The current draft entries and release history remain canonical as a combined record across both files.

- Added the WSC5B6 additive canonical validation-only runtime mode (#707): `SingleIssuePilotInput.execution_mode` and `ConcreteRuntimeConfiguration.execution_mode` select `standard` (unchanged) or `validation-only` on the one existing `_drive_lifecycle(...)` sequence. Validation-only reuses the same lease, worktree creation/inspection, cancellation checkpoints, frozen-test validator, changed-path containment, cleanup, release, quarantine, and #698 evidence-return contracts, and branches only around executor dispatch and the post-executor path check. It dispatches no executor (`executor_dispatch_attempts = 0`, `executor_called = false`, `executor_started = false`), never claims termination confirmation, constructs no `PosixProcessExecutor`, adds no no-op executor, and runs each bound validation command at most once while returning the exact retained `FrozenTestValidationResult`. The mode is bound into the canonical pilot result identity, runtime observation, and configuration fingerprint; unsupported, drifted, or mismatched modes and misplaced executor authority fail closed before any adapter runs. Standard-mode signatures, lifecycle behavior, and completion invariants are unchanged. No second lifecycle, runner, validator, scheduler, queue, retry, persistence path, workflow, provider call, network behavior, credential, AI invocation, concurrency, or arbitrary shell execution was added.
- Added the WSC5B5 bounded concrete-runtime evidence return contract (#698): `ConcreteRuntimeExecutionOutcome` and `run_concrete_runtime_entrypoint_with_validation_evidence(...)` return the canonical `SingleIssueRuntimeOutcome` together with the exact immutable `FrozenTestValidationAdapter.last_result`, or explicit `None` when validation was not reached. The existing runtime-only entrypoint remains backward compatible and delegates through the same single construction and invocation path. No validation rerun, retry, scheduler, workflow, provider, credential, persistence, publication, AI invocation, concurrency, or external write was added.
- Added closed-loop and historical `0.1.1-draft` entries that previously followed these records in `CHANGELOG.md`; this companion preserves the structural split boundary introduced for #883 without changing release semantics.
